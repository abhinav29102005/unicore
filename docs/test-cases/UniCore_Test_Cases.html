Short Description: Test that a student can sign in to UniCore, and that invalid credentials are rejected

Pre-conditions

The UniCore website is reachable at https://abhinav29102005.github.io/unicore/sign

A student account abhinav@unicore.edu exists with status active and the role Student

The browser is not signed in to UniCore (site data cleared or a private window is used)

API base URL, written as <API> below: https://unicore-backend.bigboyaks-account.workers.dev/api

StepActionExpected System ResponsePass/ FailComment
1Open the sign-in page URLThe system displays the sign-in page with the roles Student, Faculty, Admin and Staff. Student is selected and the card shows “Abhinav Kumar – Active Student”
2Open the browser DevTools → Network tabThe Network tab is open and recording requests
3Click the ‘Continue as Abhinav (Student)’ buttonThe request POST /api/auth/login returns status 200 with the user “Abhinav Kumar”, role “Student” and a token.
The system opens the student dashboard (/unicore/student)
4Check post-condition 1
5Send a login request with a wrong password:
curl -X POST <API>/auth/login -H "Content-Type: application/json" -d '{"email":"abhinav@unicore.edu", "password":"wrong-password"}'		The system responds with status 401 and the message “Invalid credentials”. No token is returned
6Repeat step 5 with an email that does not exist, say nobody@unicore.eduThe system responds with status 401 and the message “Invalid credentials”. No token is returned

Post-conditions

  1. The last login time of abhinav@unicore.edu is updated in the database. Check by opening <API>/auth/profile/7b669c2a40a0403f785eccd291f51b6a: lastLogin shows the time of step 3 (UTC)

Tests the happy path (steps 1–4) and failure conditions (steps 5–6).
