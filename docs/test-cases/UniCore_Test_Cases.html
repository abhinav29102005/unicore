Test case ID: UC-1.1 | Module: Authentication | Test type: Positive + negative
Status: Not run | Priority: High | Evidence / defect ID: __________

Scenario / objective

Check CSRF-protected login, a server session, and rejection of invalid credentials.

Preconditions

  • A Java UniCore API is running. Record its base URL as <API> (for local H2: http://localhost:8080/api).
  • An active Student account and its current password have been provided privately by the administrator. Use a fresh browser or API-client cookie jar.

Test data

Active Student email and current password (provided privately); one wrong password; one unknown email.

Test steps and expected result

#Test stepsExpected result
1GET <API>/auth/csrf in a fresh session.200; JSON contains a CSRF token. Keep the session cookie for the next request.
2POST <API>/auth/login with the same cookie, X-CSRF-TOKEN and the student email/password.200; response contains user.role = Student and user.rollNo. A server-side session is established; no JWT/token is returned.
3GET <API>/auth/me with the signed-in cookie.200; the same Student identity is returned.
4In another fresh session, get CSRF then POST login with the correct email and a wrong password.401 Invalid credentials; no authenticated session is created.
5Repeat with an unknown email and valid CSRF.401 Invalid credentials; the response does not reveal whether an account exists.

Postconditions

The successful account's last-login time is updated. Failed attempts do not authenticate the caller.
